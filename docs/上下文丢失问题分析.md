# CodeMax 上下文丢失问题诊断报告

## 🔴 问题描述

用户反馈：**左右脑互搏现象**
- Agent 记不住自己做了什么
- 询问用户意见后，无法获取询问过程的对话记录
- 导致 Agent 重复执行相同操作或自相矛盾

---

## 🔍 根本原因分析

### 问题 1：用户确认对话未记录到上下文

**代码位置**: `src/main/llm/agent-loop.ts:214-237`

```typescript
// 当前实现
```

**问题**:
1. ❌ 用户确认对话框的内容未记录到消息历史
2. ❌ 用户为什么取消/同意的信息丢失
3. ❌ Agent 下次调用时看不到这个交互过程

**结果**: Agent 不知道用户拒绝过某个操作，会反复尝试相同的工具调用

### 方案 2：智能工具结果截断 ⭐⭐

**修改文件**: `src/shared/context-compress.ts`

```typescript
export function truncateToolResult(content: string, config?: AgentConfig): string {
  const maxChars = config?.maxToolResultChars ?? 8000
  if (content.length <= maxChars) return content
  
  // ✅ 智能截断：保留开头和结尾
  const headChars = Math.floor(maxChars * 0.6)  // 60% 给开头
  const tailChars = Math.floor(maxChars * 0.3)  // 30% 给结尾
  
  const head = content.slice(0, headChars)
  const tail = content.slice(-tailChars)
  const omittedChars = content.length - headChars - tailChars
  
  return `${head}\n\n[...省略 ${omittedChars} 个字符...]\n\n${tail}`
}
```

**效果**:
- ✅ 保留结果的开头（通常是执行结果）
- ✅ 保留结尾（通常是错误信息或总结）
- ✅ Agent 能看到关键信息

### 方案 3：优先保留关键消息 ⭐⭐⭐

**修改文件**: `src/shared/context-compress.ts`

```typescript
export function trimContext(messages: MutableMessage[], config: AgentConfig): void {
  // ✅ 标记关键消息（包含用户确认/拒绝）
  const criticalMessages = new Set<number>()
  
  messages.forEach((msg, idx) => {
    if (msg.role === 'tool') {
      const content = msg.content?.toLowerCase() || ''
      // 用户交互记录标记为关键
      if (content.includes('用户拒绝') || 
          content.includes('用户取消') || 
          content.includes('用户同意')) {
        criticalMessages.add(idx)
        // 同时保护前面的 assistant 消息（tool_calls）
        if (idx > 0 && messages[idx - 1].role === 'assistant') {
          criticalMessages.add(idx - 1)
        }
      }
    }
  })
  
  // ✅ 压缩时优先保留关键消息
  // ... 压缩逻辑
}
```

**效果**:
- ✅ 用户交互记录不会被删除
- ✅ 长会话中 Agent 仍能记住关键决策
- ✅ 减少"失忆"问题
